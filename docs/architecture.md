# 当前架构：基金筛选与程序改进建议

DSH负责模型会话与工具调用，三个薄TypeScript插件通过stdin JSON调用同一Python包。没有新增Agent框架、服务或数据库。

```text
公开基金目录 + 26主题基金池 + 历史净值/分红/状态
                  ↓
固定筛选程序JSON → vn.py算子解释器 → 同类评分、状态过滤、5只推荐
                                      ↓
                       日报数值 / 全池排名 / 图表
                                      ↓
                 DSH独立日期会话解释 → 日报模型分析
                                      ↓
            成熟信号诊断 + 名单变化 → DSH周报 → 未执行的程序建议
```

每日分析插件读取新筛选报告并生成解释；算子迭代建议插件读取当周反馈并提出具体表达式；评测插件提供固定程序的1/5期信号诊断。报告会话在JS桥与Python入口按报告ID、日期和类型双重隔离，禁止读取月末未来信息、运行候选或修改程序。

`strategies/screening-current.json` 提供因子模板，构建批次时加入主题分散规则，并将实际执行的程序保存在该批次的 `program.json`。`runtime/dqr/product.py` 保留逐基金历史，将时序计算与成熟基金横截面排名分为两步。模型收到实际算子结果后才解释，不决定原始数据和评分结果。当前只有初始程序，没有执行优化或晋升。

vn.py复用固定版本的Alpha源码及ArrayManager数值方法，保留许可证和来源哈希。受限AST解释器支持自定义表达式算子，禁止任意导入、属性、未来滞后及无限递归。净值只作为净值派生序列使用，不伪造OHLCV。

OpenEvolve的Program/ProgramDatabase代码保留，用于旧候选评测归档；新日报/周报直接保存可核查的JSON报告，不为了展示建议启动搜索框架。RD-Agent不参与。

旧 `engine.py`、`monthly.py`、`daily.py` 和两基金配置保留兼容，只有显式指定旧快照时才进入这些模拟功能。它们与新筛选主流程的产物目录、程序文件及评测口径分开。

发布前依次核验原始响应、因子与名单、模型持久会话、正文数字和展示一致性。`publication.py` 将每个已发布日期解析到其原始批次；`update-daily.py` 只生成当天报告，并读取历史发布的真实名单计算周报反馈。模型失败时保留上次发布。原始响应以内容哈希归档，新增抓取保留逐页来源引用。

本机只读入口由 `scripts/serve-product.py` 提供，绑定127.0.0.1。定时任务尚未安装。
