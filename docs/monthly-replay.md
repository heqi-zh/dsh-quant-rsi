# 月度回放与真正的模型日报、周报

当前入口分两步：先由实际 vn.py 算子和固定基金模拟器生成数据，再逐份调用 DSH 模型生成分析。没有用预写建议模板冒充模型分析。

## 运行

```sh
.venv/bin/python scripts/run-month.py --snapshot cf7f626a9fde7b73baf406ad3fc7f4938b546be65f527918888e0e73d13dab07 --month 2026-09
.venv/bin/python scripts/analyze-month.py --replay <上一命令返回的replay_id> --workers 2
```

省略 month 默认选取快照最新共同净值月的前一个月。当前程序要求 100 个共同净值观察值预热。完整月份覆盖不足时拒绝回放。

`analyze-month.py` 可用 `--date YYYY-MM-DD --kind daily|weekly` 只补一份；默认续跑全部，跳过已验证且证据未变的报告。已终止会话不会被当作完成。历史 `run-month.py --dsh` 仅用于三个插件读取结果的冒烟检查，不替代逐份模型分析。

注意：同一版本重新运行计算回放会重写该版本的计算报告；请先完成计算再运行模型分析。若只补模型报告，直接续跑 analyze-month.py。

## 计算部分

当前选定程序是 `strategies/operators-current.json`，含两个自定义组合算子、16 个具名因子和加权评分：动量、均线趋势、下行波动与回撤的横截面排名共同决定评分，其余因子用于解释。评分高的基金获得 80% 目标配置，每周调仓。因子值、表达式、实际调用的函数均进入报告。

自然日晨报只含严格早于当天的净值和模拟状态；无新净值时保持同一证据。模拟从月初现金开始、每日状态连续。每周日及月末生成周报证据。净值公布时刻不可得，采用次日可见假设；成交决策只用前一共同净值日及更早的数据，周调仓可能在周二触发。

赎回到账前不能申购，确认前不能赎回，资金不足时部分执行，没有自动补单。对照只匹配初始暴露，不声称逐日风险匹配。月末整段评测与月末当天晨报截止点不同。

## 模型部分

每份报告使用独立 DSH 会话。模型只能调用该报告的 context 和 save 工具，无法读取其他日期或月末结果、生成候选、运行优化和切换程序。上下文包含计算证据、当前程序与算子目录。模型必须提交至少三个精确标量证据引用；保存时检查字段与原值一致。

日报解释算子贡献、信号冲突、配置偏离、费用与在途现金。周报提出明确因子名、可见的表达式修改和理由，标为未执行、未评测。精确引用校验能证明引用正确，不保证模型所有推断都正确；报告明确区分观察和推断。

## 产物

`data/monthly/<replay_id>/`：

- index.md：月度汇总及全部报告链接。
- daily/、weekly/：Markdown 和 JSON，程序字段与 model_analysis 分开。
- program.json、operators.json、operator-trace.json：程序定义、86 个算子目录、实际函数调用。
- evaluation.json：曲线、持仓、成交、指标、基线与配置。
- manifest.json：数据及实现版本、报告日期与计算摘要。
- openevolve/：真实 ProgramDatabase 保存的程序和评测记录。
- analysis-run.json：最近一次模型批次的完成/失败记录；单份报告的 verified_session 指向独立证据。

`data/dsh-analysis-runs/<id>/` 保存任务、事件、错误日志及校验记录。主流程校验模型确实先读证据，再保存自己的文字，报告内容与调用一致，且选定程序未变。模型密钥不写入产物。

没有接入支付宝账户或实际交易；申赎规则仍需产品级核实。更多算子可用不代表策略已有效，当前程序未经优化。
